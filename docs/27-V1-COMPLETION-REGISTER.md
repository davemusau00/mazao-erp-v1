Every new slice needs typed contracts, permissions, transaction/idempotency/audit/version evidence, migration upgrade/fresh/rerun, negative cases, browser acceptance and integration documentation. Deploy only the accepted exact commit and preserve the prior API/static release and forward database history. Protect all unrelated VPS services.

Acceptance must include first-use → first sale → cash close; split/manual tender and replay; package/recipe/count/transfer; restaurant fire→complete→settle; guest deposit→folio→partial settlement→checkout→clean; customer/AP reconciliation; period close; 100 permitted offline sales and repeated replay; tenant/role/device adversarial checks; the seven requested viewports and physical/scanner checks where configured.

Explicitly deferred: automated M-Pesa/eTIMS, loyalty, public booking, advanced payroll, native business applications, AI insights, reseller billing and advanced revenue management. Manual payment confirmation is implemented within the limits above. Ordinary hotel/restaurant completion and bounded offline accounting remain v1 work; restaurant and offline financial operations stay disabled until accepted.

S00-06 navigation keeps the existing authorization boundary: `finance.view` opens Money; server-reported `finance.manage` gates expense/supplier/matching actions and `finance.close` gates period changes. Stock receiving access alone does not expose supplier accounting. Bills support one complete delivery value; expenses use supported categories and noncash accounts; incoming statements support 1–2,000 transactions and periods of up to 367 days. These are bounded online workflows, not complete purchasing or financial statements.

S00-06 also corrects recovery navigation: retained `finance.*` commands open Money rather than Shifts. Direct links select the matching supplier, expense, M-Pesa or period area, and workspace readiness observes that area's real accounting reads instead of an unrequested trial-balance endpoint. The registry and visible Money descriptions expose the supported limits; restaurant and offline financial actions remain unavailable.

S00-04 count and import history now display the server's matching total, support continuation beyond the first 50 records, and send search terms to the full authorized server query. A failed continuation retains the existing rows and cursor for an explicit retry. Aborted or superseded history reads cannot replace the current results. History navigation does not change saved count drafts, stock posting or reviewed CSV apply semantics. Browser evidence and per-fix boundaries are recorded in [feature availability and history navigation](52-FEATURE-AVAILABILITY-HISTORY-NAVIGATION.md), with overall acceptance in [the execution register](48-CODEBASE-TRUTH-EXECUTION.md).
